# 말하기 측정값: 말하기 속도·멈춤, 발음 정확도 지원 여부 (2026-10-14)

> **현재 상태 (2026-10-15)**
>
> | 항목 | 상태 |
> |---|---|
> | Whisper 음성 인식, 텍스트 일치율, 말하기 속도·멈춤 측정, 학생·선생님 화면 상태 표시 | 완료(구현) |
> | 속도·멈춤 측정의 아동 음성 정확도, 0.25초 멈춤 기준의 아동 적용 | 검증 대기(8장) |
> | 아동 음성 검증 시작(책임자·동의·윤리·전문가) | 외부 결정 필요(8.9) |
> | 검증 도구(`speechValidation`) | 완료(합성음 자체 점검만, 8.10·8.11) |
> | 발음 정확도 평가 | 미구현 — 화면 '준비 중'(4·9장) |
>
> 텍스트 일치율은 발음 정확도 점수가 아니다. 말하기 속도와 멈춤은 계산된 측정값이며 검증된 말하기 능력 점수나 종합 유창성 점수가 아니다. 측정값이 있다는 것만으로 측정 정확도가 검증된 것은 아니다.

## 1. 원인: 결과 화면이 항상 '미평가'였던 이유

### 기존 흐름

1. **녹음**: 브라우저가 WAV(16-bit PCM)로 녹음한다.
2. **업로드**: `POST /api/v1/speech/analyze`(multipart)로 보낸다.
3. **저장**: `AudioStorageService`가 녹음 파일을 저장한다.
4. **음성 인식**: `LocalWhisperRecognitionService`가 처리한다.
   - 무음·길이를 확인한다.
   - 앞뒤에 무음 1초를 붙인다.
   - Silero VAD(`whisper-vad-speech-segments`)로 말소리 구간을 찾는다.
   - whisper.cpp로 인식한다.
5. **비교·분석**:
   - `TranscriptComparator`가 텍스트 일치율을 계산한다.
   - `SpeechAssessmentEvaluator`가 오류 후보, 판정 보류, VAD 발화 시간(`timing`)을 만든다.
6. **결과 저장**: `speech_analyses`에 저장한다. `match_rate`, `comparison_json`, `assessment_json`(분석 결과 JSON)이다.
7. **조회**: `GET /api/v1/speech/analyses/{id}`가 `toResponse`를 거쳐 화면(`SpeechAnalysisResult`)에 결과를 보낸다.
8. **학습 기록**: `POST /api/v1/practice/attempts`로 기록을 저장한다.

### 원인

- 화면의 '발음 정확도·말하기 속도·유창성'은 `pronunciationScore`·`speechRateScore`·`fluencyScore` 컬럼만 표시했다.
- 이 컬럼은 외부 제공자 경로(`SPEECH_ENGINE=external`)에서만 채워진다. 로컬 경로는 항상 비워 둔다.
- 그래서 로컬 분석 결과는 언제나 '미평가'였다.
- 반면 로컬 경로는 VAD 구간 기반 발화 시간(`speechTiming`)을 이미 계산·저장하고 있었다. 이 값은 선생님 검토 화면에서만 쓰였다.

### 확보할 수 있는 값

| 값 | 위치 |
|---|---|
| 녹음 파일 | 분석 중에만 존재. 일반 연습은 인식 직후 삭제한다 |
| 녹음 시간 | `WavAudio.durationMs()` |
| 말소리 구간 | VAD 결과. 원본 녹음 기준 ms |
| 인식 텍스트 | whisper.cpp 결과 |
| 목표 문장 | 문항(`exercise_items`) |

- 녹음 파일이 삭제되므로 측정값은 분석 시점에 계산해 `assessment_json`에 저장한다.

## 2. 구현 (DB 스키마 변경 없음)

- `assessment_json`에 `metrics`(버전 `speech-metrics-v1`)를 추가로 저장한다.
- API 응답에는 `speechMetrics`로 넣는다.
- 그대로 둔 것:
  - 텍스트 일치율 계산
  - `analysis_version`(`jamo-align-v1`)
  - 점수 컬럼(`speech_rate_score`·`fluency_score`·`pronunciation_score`). 측정값을 0~100 점수로 바꾸지 않는다.

| 항목 | 상태 | 계산 |
|---|---|---|
| 발음 정확도 | 항상 `NOT_SUPPORTED`(`NO_PRONUNCIATION_MODEL`) | 음향 기반 발음 평가 모델이 없다. 인식 텍스트로 발음 점수를 만들지 않는다 |
| 말하기 속도 | `MEASURED` / `NOT_SUPPORTED` / `UNAVAILABLE` | 아래 정의 참고 |
| 멈춤(유창성 참고) | `MEASURED` / `NOT_SUPPORTED` / `UNAVAILABLE` | 아래 정의 참고. 종합 유창성 점수가 아니다 |

### 말하기 속도

- `syllablesPerSecond` = 인식 텍스트의 한글 음절 수 ÷ **발화 구간**(첫 말소리 시작 ~ 마지막 말소리 끝, 멈춤 포함)
- `articulationRate` = 음절 수 ÷ 말소리 시간(멈춤 제외)

### 멈춤

- 발화 구간 안에서 VAD 말소리 구간 사이 무음이 **250ms 이상**이면 멈춤으로 센다.
- 기록 항목: 횟수, 합, 최장, 발화 구간 대비 비율

### 상태 구분

| 상태 | 뜻 | 사유 |
|---|---|---|
| `MEASURED` | 측정함 | |
| `NOT_SUPPORTED` | 이 항목은 하지 않음 | 발음 모델 없음, 낱말 문항(`WORD_ITEM`) |
| `UNAVAILABLE` | 이번 녹음에서 측정 못 함 | VAD 없음(`VAD_UNAVAILABLE`), 판정 보류(`ASSESSMENT_HOLD`), 4음절 미만 또는 발화 1초 미만(`UTTERANCE_TOO_SHORT`, 속도만) |

- **분석 실패**: 무음·인식 실패 등은 기존처럼 HTTP 422/5xx를 돌려주고 `status=FAILED`로 남기며, `speechMetrics`는 없다.
- **이전 분석**: `metrics`가 없으면 `speechMetrics`=null이고, 화면은 기존 '미평가'를 유지한다. 값을 새로 지어내지 않는다.

### 녹음 여유 시간의 영향

- 녹음 전체 시간(버튼 누른 뒤 ~ 멈춘 시점)으로 나누면, 앞뒤 여유가 길수록 속도가 느리게 나온다.
- 그래서 녹음 전체 시간을 쓰지 않고 VAD 첫 구간 시작 ~ 마지막 구간 끝만 쓴다.
- 같은 구간을 1.5초 뒤로 옮기고 앞뒤 여유를 늘려도 값이 같음을 단위 테스트로 확인했다.

### VAD 측정 특성 (합성음으로 확인)

- 기본값:
  - 100ms 미만 무음은 한 구간으로 합친다.
  - 구간 앞뒤에 여유(30ms)를 붙인다.
- 단어 사이 0.7초 무음을 넣은 합성음에서 VAD 무음은 0.58초로 측정되었다. **실제보다 약 0.1초 짧다.**
  - 따라서 250ms 기준은 실제 무음 약 0.35초 이상에 해당한다.
- 삽입 무음을 150 → 300 → 600 → 1200ms로 늘리면 측정 무음도 같은 폭(±20ms)으로 늘었다.

### 화면 표시

- 측정값은 막대·점수로 그리지 않는다.
- 문구 예: "1초에 3.9글자 · 9글자를 2.3초 동안 말했어요", "1번 멈췄어요 · 가장 길게 0.6초"
- 아래에 "점수나 유창성 평가가 아니에요"를 함께 적는다.
- 발음 정확도는 '미지원 · 발음을 평가하는 모델이 아직 없어요'로 표시한다.

## 3. 한계

- **음절 수**는 인식 텍스트 기준이다.
  - Whisper는 반복·간투사("어…")를 지우거나 고쳐 적을 수 있다. 그래서 실제 발화 음절보다 적게 셀 수 있다.
  - 인식이 틀리면 음절 수도 틀린다.
- **검증 범위**: VAD·임계값은 성인 합성음(macOS TTS)으로만 확인했다.
  - 아동 음성, 소음 환경, 속삭임에서의 정확도는 검증하지 않았다.
- **멈춤 기준**:
  - 250ms는 무성 휴지 연구에서 흔히 쓰는 기준이다. 아동·언어재활 맥락의 정상 범위·기준값이 아니다.
  - 그래서 '좋다/나쁘다' 판정이나 종합 유창성 점수를 만들지 않았다.
  - 말더듬 특성(반복·연장·막힘)은 VAD만으로 구분할 수 없다.
- **표시 범위**: 6장 참고(2026-10-15에 학생·선생님 화면을 같은 공통 표시로 맞췄다).

## 4. 발음 정확도: 필요한 기술과 연동 방안 (구현하지 않음)

- **현재 상태**: 프로젝트에 음향 기반 발음 평가 모델이 없다.
  - Whisper 인식 결과는 틀린 발음을 맞는 말로 고쳐 적거나 그 반대로 적을 수 있다.
  - 따라서 인식 결과로는 발음 점수를 만들지 않는다.

| 방안 | 내용 | 확인한 사실 | 고려할 점 |
|---|---|---|---|
| A. 한국어 음소 인식 모델 + 정렬 기반 평가(GOP 등) | wav2vec2 CTC 음소 인식기로 음소 사후확률을 구하고, 목표 문장의 표준 발음 음소열(표준 발음법 변환)과 비교한다 | [slplab/wav2vec2-xls-r-300m_phone-mfa_korean](https://huggingface.co/slplab/wav2vec2-xls-r-300m_phone-mfa_korean): MFA-IPA 음소 출력, 원어민 성인 낭독 108시간 학습, PER 3.88%(모델 카드), Apache-2.0 | 성인 낭독 학습이라 아동 음성 성능이 미검증이다. 문자→표준 발음 음소 변환기가 필요하다. 서버 로컬에서 Python 추론 프로세스(또는 ONNX)를 whisper.cpp처럼 별도 실행 파일로 붙일 수 있다 |
| B. 강제 정렬(Montreal Forced Aligner) | 목표 음소열과 음성을 맞춰 음소별 구간·정렬 점수를 얻는다 | 한국어 MFA 사전 CC BY 4.0 ([문서](https://mfa-models.readthedocs.io/en/latest/dictionary/Korean/Korean%20MFA%20dictionary%20v2_0_0a.html)) | 정렬 가능도는 발음 정확도 점수가 아니다. A의 보조(음소 구간 제공)로 쓴다 |
| C. 외부 발음 평가 API(예: Azure AI Speech 발음 평가) | 음성 + 목표 문장을 보내 음소·단어 단위 점수를 받는다 | 이번 조사에서 공식 지원 언어표로 ko-KR 발음 평가 지원 여부를 확정하지 못했다([지원 언어](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support)) | 유료다. 아동 음성을 외부로 전송하므로 보호자 동의 항목 추가와 국외 이전 고지가 필요하다. 이번 작업에서는 호출하지 않았다 |

### 연동 구조 (A 기준)

- `SpeechRecognitionService`처럼 `PronunciationAssessmentService` 인터페이스를 둔다.
- 일반 연습 녹음은 인식 직후 삭제하므로, 평가를 분석과 같은 시점에 실행한다.
- 결과는 `metrics.pronunciation`을 `MEASURED`로 바꾸고 음소별 근거를 함께 저장한다.
- 모델이 없거나 실패하면 지금처럼 `NOT_SUPPORTED`/`UNAVAILABLE`로 둔다.

### 도입 전 필요한 것

- 아동 음성 평가 데이터: 언어재활사가 판정한 음소 단위 정답
- 점수와 언어재활사 판정의 일치도 검증
- 점수 표시 정책: 아동에게 점수를 보일지

## 6. 평가 상태 표시 정리 (2026-10-15)

학생 결과와 선생님 화면(연습 기록 패널·음성 검토)이 같은 공통 컴포넌트 `features/speechMetrics/components/SpeechMetricList.tsx`로 같은 저장값(`speechMetrics`)을 표시한다. 문구만 대상에 맞게 다르고 의미는 같다.

| 표시 | 조건(저장 데이터) | 학생 문구 | 선생님 문구 |
|---|---|---|---|
| 측정값 | `status=MEASURED` | 초당 3.9글자 · 9글자를 2.3초 동안 말했어요 / 1번 멈췄어요 · 가장 길게 0.6초 | 초당 3.9글자 · 9음절 / 발화 2.3초 · 멈춤 제외 초당 5.2음절 / 1회 · 최장 0.6초 · 합계 0.6초 |
| 준비 중 | 발음 정확도(`NO_PRONUNCIATION_MODEL`). 측정값이 없는 이전 기록이어도 발음 분석 기능은 없으므로 같다 | 준비 중 · 발음을 분석하는 기능을 준비하고 있어요. / 현재는 발음 정확도 점수를 제공하지 않아요. | 준비 중 · 발음 분석 준비 중 · 발음 평가 모델이 없어 발음 정확도를 제공하지 않습니다. |
| 해당 없음 | `NOT_SUPPORTED` + `WORD_ITEM` | 낱말 하나는 재지 않아요 | 낱말 문항은 측정하지 않음 |
| 측정 불가 | `UNAVAILABLE` + 이유 | 녹음이 또렷하지 않아 재지 않았어요 등 | 판정 보류 녹음이라 측정하지 않음 등 |
| 기록 없음 | `speechMetrics`=null(측정 기능 이전 기록) | 이 기록에는 측정값이 없어요 | 측정 기능 이전에 저장된 기록이라 측정값이 없습니다 |
| 분석 실패 / 분석 중 | 분석 `status`=FAILED / PROCESSING | 측정 항목 대신 상태만 표시(준비 중을 표시하지 않음) | 같음 |

- '준비 중'은 하늘색(info) 배지, 나머지 미측정 상태는 회색(neutral), 분석 실패만 붉은색(danger)이다. 모든 상태는 배지 글자와 설명으로도 구분한다(색만으로 구분하지 않음).
- 측정값은 막대·점수·등급으로 그리지 않는다. 화면의 막대는 텍스트 일치율 하나뿐이다.
- '준비 중'은 기능 개발 상태다. 진행 표시(스피너·애니메이션)를 쓰지 않아 분석이 진행 중인 것처럼 보이지 않게 했다.
- 외부 제공자 점수(SPEECH_ENGINE=external)가 있으면 기존처럼 그 점수를 표시한다(선생님 음성 검토·학생 외부 제공자 결과·분석 리포트). 점수가 없을 때의 '미평가'를 '발음 분석 준비 중'으로 바꿨다.
- API: 선생님 연습 기록 `GET /teachers/me/students/{id}/practice-attempts`의 각 행에 `speechMetrics`를 추가했다(학생 분석 조회와 같은 저장값, 내부 JSON 원문은 내보내지 않음). 기존 필드는 그대로다.
- 그대로 둔 '미평가': 외부 제공자 결과 화면의 점수 항목(제공자가 값을 주지 않은 경우), 학습 기록·세션 결과의 텍스트 일치율 없음 표시(발음 평가가 아니라 일치율이 없는 기록).

## 7. 아동 음성 검증 계획 (실행 전)

현재 속도·멈춤 측정은 성인 합성음(macOS TTS)으로만 확인했다. **실제 아동 음성 데이터는 수집하지 않았고, 아래 검증은 아직 수행하지 않았다.** 검증 전에는 측정값을 아동의 정상 말하기 기준과 비교하거나 '정상/느림' 같은 판단으로 표시하지 않는다.

### 7.1 왜 필요한가

- 아동 음성은 성인보다 기본 주파수가 높고 조음이 불안정해 Whisper 인식과 Silero VAD 구간 검출이 성인 합성음과 다르게 동작할 수 있다.
- 아동은 반복("오, 오늘은"), 머뭇거림("어…"), 긴 멈춤, 작은 목소리가 잦다. 이런 발화에서 음절 수(인식 텍스트 기준)와 멈춤(VAD 기준)이 얼마나 틀리는지 모른다.
- 가정·센터의 소음과 마이크(노트북 내장·태블릿·이어폰) 차이가 VAD에 영향을 준다.

### 7.2 데이터 수집 조건 (사전 확인 사항)

- 수집·이용의 적법한 근거와 법정대리인(보호자) 동의를 받는다. 기존 VOICE 동의(서비스 제공 목적)와 별도로 '측정 기능 검증 목적' 동의가 필요한지 법적 검토를 받는다.
- 검증용 녹음은 서비스 DB가 아닌 분리된 저장소에 두고, 접근 권한·보관 기간·파기 절차를 정한다. 이름 등 식별 정보는 녹음 파일과 분리(가명 ID)한다.
- 외부 서비스로 전송하지 않는다(현재 측정은 모두 서버 로컬).
- 기관 IRB(연구윤리) 심의 대상인지 확인한다.

### 7.3 표본 설계

| 축 | 구성 |
|---|---|
| 연령 | 서비스 대상 연령대(예: 5~7세, 8~10세, 11~13세)별 |
| 학습자 유형 | 일반 아동 / 언어재활 아동(조음·유창성 어려움) |
| 문항 | 낱말, 짧은 문장(2~3어절), 긴 문장(4어절 이상) — 기존 연습 콘텐츠 사용 |
| 발화 특성 | 매끄러운 발화, 정상적인 짧은 쉼, 긴 멈춤(1초 이상), 반복, 간투어(어·음), 끝을 흐림, 작은 목소리 |
| 녹음 환경 | 조용한 방 / 생활 소음(TV·대화) / 센터 소음, 기기별 마이크 2~3종 |

- 각 칸에 최소 표본 수를 정해(예: 칸당 20녹음 이상) 문장 유형·환경별 결과를 따로 볼 수 있게 한다.

### 7.4 기준 정답 만들기

- 훈련된 전사자 2명이 각 녹음을 Praat 등 음성 편집 도구로 보고 독립적으로 표시한다.
  - 실제 발화 음절 수: 반복·간투어를 포함한 수와 제외한 수를 각각 센다.
  - 말소리 구간 시작·끝, 각 무음 구간의 시작·끝(10ms 단위).
  - 반복·간투어·연장의 위치.
- 두 전사자의 차이를 비교해 일치도(무음 경계 차이 평균, 멈춤 개수 일치율, 음절 수 일치율)를 기록하고, 불일치는 제3자(언어재활사)가 조정한다.
- 기준 정답에서 시스템과 같은 정의로 값을 계산한다: 발화 구간, 말소리 시간, 무음 ≥250ms(또는 비교할 다른 기준)의 멈춤 수·합·최장, 속도 = 음절 ÷ 발화 구간.

### 7.5 비교 방법

- 녹음마다 시스템 값과 기준 정답 값을 나란히 저장한다(`speechMetrics` 원값 + 정답 + 녹음 조건).
- 지표:
  - 속도: 절대 오차(음절/초), 상대 오차(%), Bland–Altman 차이 평균과 95% 일치 한계
  - 멈춤 수: 정확히 일치한 비율, 개수 차이 분포
  - 멈춤 시간·최장 멈춤: 절대 오차(ms). VAD가 무음을 약 0.1초 짧게 재는 편향이 아동 음성에서도 일정한지 확인
  - 음절 수: 인식 텍스트 음절 수 − 실제 발화 음절 수(반복·간투어 포함/제외 각각). Whisper가 반복·간투어를 지워 생기는 과소 계수를 따로 집계
- 실패율: 분석 실패(422 등), 측정 불가(VAD_UNAVAILABLE·ASSESSMENT_HOLD·UTTERANCE_TOO_SHORT)의 비율을 문장 유형·환경·연령별로 기록
- 결과는 칸별 표와 전체 요약으로 `docs/testing/`에 기록하고, 측정 버전(`speech-metrics-v1`)과 모델·VAD 설정을 함께 남긴다.

### 7.6 판단 기준과 화면 안내

- 사전에 허용 오차를 정하고(예: 속도 상대 오차 중앙값 15% 이내, 멈춤 수 일치율 80% 이상 — 수치는 언어재활사 검토 후 확정) 칸별로 통과 여부를 판단한다.
- 통과하지 못한 조건(예: 소음 환경, 긴 문장, 언어재활 아동)에서는 다음 중 하나를 적용한다.
  - 측정값 옆에 "이 녹음 환경에서는 측정값이 부정확할 수 있어요" 안내를 표시
  - 해당 조건에서는 측정 불가로 처리
- 모든 조건에서 검증이 끝나기 전까지 지금처럼 "녹음에서 잰 값이며 점수나 유창성 평가가 아니에요"(학생), "아동 음성 기준으로는 아직 검증하지 않았습니다"(선생님) 문구를 유지한다.
- 멈춤 기준(250ms)을 아동용으로 바꿀지는 검증 결과와 전문가 검토 후 결정하고, 바꾸면 측정 버전을 올린다(기존 기록은 기존 버전 값으로 둔다).

### 7.7 전문가 검토가 필요한 항목

- 언어재활사: 멈춤 기준(250ms)의 아동 적용 타당성, 반복·간투어를 음절 수에 포함할지, 말더듬 특성(반복·연장·막힘)과 멈춤 측정의 관계, 아동·보호자에게 측정값을 보여 주는 방식과 문구, 허용 오차
- 개인정보·법률 담당: 검증용 수집 동의 항목, 보관·파기, IRB 대상 여부
- 음성 처리 담당: VAD 파라미터(임계값·최소 무음) 조정 여부, 인식 모델 차이의 영향

### 7.8 아직 확인하지 않은 것

- 아동 음성에서의 인식 정확도, VAD 구간 정확도, 측정 오차와 실패율
- 소음·마이크 종류별 차이
- 반복·간투어가 많은 발화에서의 음절 과소 계수 크기
- 아동 연령별 말하기 속도·멈춤의 정상 범위(문헌·전문가 자문 필요)

7장의 계획을 실행할 수 있도록 데이터 조건, 기준 정답 작성 규칙, 검증 매트릭스, 실행 도구를 정했다. **실제 아동 음성 검증은 수행하지 않았다**(8.1 참고). 현재 측정값과 화면 문구는 '아동 음성 미검증' 상태 그대로다.

| 연구윤리 | 기관 IRB 심의 대상인지, 면제·승인 절차 | 연구 책임자 |

### 8.3 기준 정답 작성 규칙(초안, 언어재활사 검토 후 확정)

- **도구**: Praat 등 파형·스펙트로그램을 보는 로컬 도구. 10ms 단위로 표시한다.
- **말소리 구간(ref_speech_segments)**: 사람 발화(낱말·간투어·반복 포함)가 들리고 파형이 보이는 구간. 숨소리·입맛 다시는 소리·배경 소음은 말소리가 아니다. 무성 파열음 앞의 폐쇄 구간(약 100ms 미만)은 말소리에 포함한다.
- **무음 구간**: 이웃한 말소리 구간 사이. 멈춤 = 무음 ≥ 250ms(시스템과 같은 정의로 비교하기 위함, 아동 적용 타당성은 별도 검토). 100~250ms 무음은 '짧은 무음'으로 따로 센다(보고서 `ref_short_silences`).
- **발화 구간**: 첫 말소리 시작 ~ 마지막 말소리 끝. 녹음 앞뒤 여유는 빼고, 말소리 없는 녹음은 비운다.
- **음절 수**: 실제로 소리 낸 한글 음절. 두 가지를 모두 적는다.
  - `ref_syllables_with_disfluency`: 반복("오, 오늘은"=4)·간투어("어", "음"=각 1)·고친 말 포함
  - `ref_syllables_without_disfluency`: 반복·간투어를 뺀 최종 발화 음절
  - 목표 문장과 다르게 말했으면 목표가 아니라 실제 소리 낸 음절을 센다. 알아들을 수 없는 음절은 음절 수에 넣고 notes에 표시한다.
- **전사자**: 서로 독립된 2명이 따로 표시(annotator=A·B) → 차이가 있는 녹음은 언어재활사가 조정해 annotator=FINAL 행을 만든다. 조정 근거는 notes에 남긴다.
- **전사자 간 일치도**: 도구가 녹음마다 멈춤 수 일치, 음절 수 일치, 구간 경계 평균 차이(ms)를 계산한다. 일치도가 낮은 조건(예: 소음·속삭임)은 기준 정답 자체가 불확실하므로 결과 해석에서 따로 다룬다.

### 8.4 비교 지표

| 대상 | 지표 | 계산 |
|---|---|---|
| 말하기 속도 | 오차 평균(편향), 평균 절대 오차(MAE), 상대 오차 절댓값 중앙값(%) | 시스템 `syllablesPerSecond` − 기준(음절 ÷ 기준 발화 구간). 기준 음절은 반복·간투어 포함/제외 두 가지로 각각 계산 |
| 음절 수 | 시스템 음절 − 기준 음절 | Whisper가 반복·간투어를 지우는 정도. 포함 기준과 제외 기준의 차이로 본다 |
| 발화 구간 | 오차 평균(ms) | 시스템 `utteranceMs` − 기준. VAD 구간 여유의 영향 |
| 멈춤 수 | 정확히 일치한 비율(%), 차이 절댓값 평균 | 시스템 `pauseCount` − 기준 |
| 멈춤 시간 | 최장 멈춤 오차 평균·MAE, 멈춤 합 MAE(ms) | VAD가 무음을 짧게 재는 편향의 크기와 일정성 |
| 실패·미측정 | 분석 실패 수, 속도 해당 없음·측정 불가 수(사유별), 측정됐지만 기준 음절 없는 수 | results.tsv의 `analysis_status`·`rate_reason`·`pause_reason` |

- 모든 지표를 전체, 문항 유형, 연령대, 학습자 유형, 조건 태그별로 나눠 본다.
- 오차는 '측정된' 녹음만으로 계산한다. 측정 불가·실패는 따로 센다(측정값이 없는 녹음을 0으로 넣지 않는다).
- 도구는 합격·불합격을 판정하지 않는다. 허용 오차는 전문가 검토 후 정한다(7.6).

### 8.5 검증 매트릭스(조건 태그)

각 녹음에 아래 태그를 붙이고(여러 개 가능), 녹음마다 입력 조건·기준 정답·기대 결과·측정 오차·실패 여부가 results.tsv 한 행에 남는다.

| 구분 | 태그 | 입력 조건 | 기대 결과(시스템 정의상) | 확인할 오차·실패 |
|---|---|---|---|---|
| 문항 길이 | (item_type) WORD / SENTENCE, 어절 수는 target_text로 | 낱말, 짧은 문장(2~3어절), 긴 문장(4어절 이상) | 낱말: 속도·멈춤 해당 없음 / 4음절·1초 미만: 속도 측정 불가 | 문장 길이별 속도 오차 |
| 매끄러운 발화 | FLUENT | 멈춤·반복 없음 | 멈춤 0회 | 멈춤 과다 검출 |
| 짧은 멈춤 | SHORT_PAUSE | 0.1~0.4초 쉼 | 기준이 250ms 이상이면 멈춤 | 경계 근처 놓침·과다 |
| 긴 멈춤 | LONG_PAUSE | 1초 이상 쉼 | 멈춤으로 셈 | 멈춤 시간 과소 측정 크기 |
| 반복 | REPETITION | "오, 오늘은", 낱말 반복 | 인식 텍스트가 반복을 지우면 음절 과소 | 음절 수 차이, 속도 편향 |
| 간투어·머뭇거림 | FILLER | "어…", "음…" | 간투어가 지워지거나 말소리로 잡힘 | 음절 수 차이, 멈춤 수 차이 |
| 녹음 여유 | RECORDING_MARGIN | 말하기 전후 1초 이상 무음 | 속도·멈춤에 영향 없음 | 발화 구간 오차 |
| 소음 | NOISE_TV / NOISE_TALK / NOISE_CENTER | 생활·대화·센터 소음 | 소음이 말소리로 잡히면 발화 구간·멈춤 오차 | 실패율, 멈춤 수 차이 |
| 마이크 | MIC_BUILTIN / MIC_TABLET / MIC_HEADSET | 기기별 | | 기기별 실패율·오차 |
| 작은 목소리 | QUIET_VOICE | 속삭임·작은 소리 | 판정 보류(LOW_VOLUME) 또는 VAD 미검출 | 측정 불가 비율 |
| 너무 짧은 발화 | TOO_SHORT | 한두 음절 | 측정 불가(UTTERANCE_TOO_SHORT) 또는 판정 보류 | 오분류 여부 |
| 말소리 없음 | NO_SPEECH | 버튼만 누름·소음만 | 분석 실패(422) | 환각 인식 여부 |
| 잘린 녹음 | SPEECH_CUT_OFF | 말이 끝나기 전에 멈춤 | 판정 보류 → 측정 불가 | 오분류 여부 |
| 인식 불일치 | ASR_MISMATCH | 인식 텍스트가 실제 발화와 다름(기준 전사와 비교해 표시) | 음절 수가 실제와 달라 속도 오차 | 음절 수 차이 |

- 연령대(age_band)·학습자 유형(learner_type: GENERAL/THERAPY)별 표본 수는 검증 목적과 전문가 의견으로 정한다. 이 문서는 특정 표본 수를 충분한 기준으로 제시하지 않는다.

### 8.6 실행 도구

- 매니페스트(TSV, UTF-8, `#`로 시작하는 줄은 주석) 열: `recording_id, audio_path, target_text, age_band, learner_type, item_type(WORD·SENTENCE), conditions(|구분), annotator(A·B·FINAL), ref_syllables_with_disfluency, ref_syllables_without_disfluency, ref_speech_segments(예: 500-930;1670-2720), notes`. 한 녹음에 전사자별로 여러 행을 쓰고, 녹음 정보(audio_path 등)는 첫 행에 적는다(다음 행은 비우거나 같은 값).
- 실행:
  ```bash
  cd backend
  SPEECH_VALIDATION_MANIFEST=/검증저장소/manifest.tsv \
  SPEECH_VALIDATION_AUDIO_ROOT=/검증저장소/audio \
  sh gradlew speechValidation
  ```
  - `SPEECH_VALIDATION_AUDIO_ROOT`: 검증 녹음 폴더(없으면 매니페스트 폴더). `audio_path`는 이 폴더 기준 상대 경로만 받는다.
  - `SPEECH_VALIDATION_INCLUDE_TRANSCRIPT=1`일 때만 인식 텍스트를 결과에 적는다(기본: 적지 않음).
- **측정 전 입력 검사**(하나라도 있으면 측정하지 않고 문제 목록을 줄 번호와 함께 출력, 결과 폴더도 만들지 않음):
  - 매니페스트: 머리글, 열 개수 초과, 필수 값(recording_id·audio_path·target_text·item_type·annotator), item_type 값, 음절 수 정수·0 이상, 포함 음절 ≥ 제외 음절, 말소리 구간 없음 + 음절 > 0, 구간 형식(0 이상 정수 ms, 끝 > 시작, 겹침·맞닿음·순서), 같은 녹음의 녹음 정보 충돌, 전사자 중복, FINAL 누락
  - 경로: 절대 경로·`..`로 폴더 밖을 가리키는 경로 거부, 실제 경로(심볼릭 링크 해석)가 검증 녹음 폴더 밖이면 거부
  - **거부 위치**: 서비스 녹음 저장소(`backend/storage/audio`, `AUDIO_STORAGE_PATH`)와 E2E 녹음 저장소(`backend/build/test-db/audio`)의 파일은 검증 녹음 폴더 안에 있더라도 쓰지 않는다(출처·동의 기록 없음)
  - 녹음: 파일 존재, 16-bit PCM WAV, 기준 구간 끝 ≤ 녹음 길이(+10ms)
  - 문제 보고에는 녹음 ID·줄 번호·매니페스트에 적힌 상대 경로만 쓴다(절대 경로·녹음 내용 없음)
- 측정: 운영과 같은 단계(whisper.cpp 인식 → 빈/환각 인식은 분석 실패 → `SpeechAssessmentEvaluator`). DB를 쓰지 않고 외부로 전송하지 않는다.
- 결과: `backend/build/speech-validation/<yyyyMMdd-HHmmss>/`(같은 이름이 있으면 `-1`, `-2`… 새 폴더, 기존 결과를 덮어쓰지 않음)
  - `results.tsv`: 녹음별 입력 조건·기준 정답·시스템 상태·측정값·오차와 녹음 SHA-256(`audio_sha256`)
  - `summary.md`: 묶음별 지표(분석 실패·속도 해당 없음·측정 불가·기준 음절 없음을 따로 셈), 전사자 일치도, 매니페스트 SHA-256, 측정 버전·모델·멈춤 기준
  - 녹음·매니페스트는 읽기만 하고 복사·수정하지 않는다(자체 점검 테스트에서 실행 전후 SHA-256 동일 확인).
- 재현성: 같은 입력·같은 모델·같은 설정으로 두 번 실행해 results.tsv·summary.md가 같음을 확인했다(합성음, 8.10).
- 실제 아동 음성 매니페스트·녹음·결과는 저장소에 커밋하지 않고 검증 전용 저장소에 둔다.
- 분리: 실행기 `SpeechValidationRun`은 `unitTest`·`integrationTest`·`test`에서 제외되고 `speechValidation`으로만 실행된다. 검증 도구는 테스트 소스에만 있고 운영 코드·배포물에 포함되지 않는다. 도구의 계산·검사는 `SpeechValidationTest`, 동작은 `SpeechValidationHarnessSelfTest`(합성음)로 확인한다.

### 8.7 수행한 것과 결과 (2026-10-15)

- **하네스 자체 점검만 수행**: 합성음 매니페스트(`speech-validation/synthetic-selftest.tsv`, 5녹음)로 `speechValidation`을 실행해 보고서가 만들어지고, 시스템 상태가 운영과 같게 나오는 것을 확인했다(문장 2건 측정, 낱말 해당 없음, 잘린 녹음 측정 불가, 무음 분석 실패).
- 참고(합성음, 아동 음성 결과 아님): 진폭 기준으로 만든 기준 구간과 비교하면 VAD 발화 구간이 80~160ms 길어 속도가 3.6~6.2% 낮게 나왔고, 0.74초 무음은 0.58초로 측정되었다(−160ms). 이 값은 아동 음성 오차를 대표하지 않는다.
- **수행하지 않은 것**: 실제 아동 음성 검증, 전사자 기준 정답 작성, 전문가 검토, 허용 오차 결정, 연령별 결과.

### 8.8 화면 문구 확인

- 선생님: "점수·종합 유창성 평가가 아니며, 아동 음성 기준으로는 아직 검증하지 않았습니다" — 실제 상태(미검증)와 일치한다. 유지.
- 학생: "말하기 속도와 멈춤은 녹음에서 잰 값이에요. 점수나 유창성 평가가 아니에요." — 정상 범위·점수로 오해할 표현 없음. 유지.
- 측정값을 점수·등급·정상 범위로 바꾸는 표현은 화면에 없다(텍스트 일치율만 막대로 표시). 검증 전에는 바꾸지 않는다.

### 8.10 검증 도구 최종 점검 (2026-10-15)

- 점검에서 고친 것:
  - 입력 오류가 측정 결과(분석 실패)로 섞이던 문제: 없는 파일·WAV가 아닌 파일이 '분석 실패'로 집계되었다 → 측정 전에 입력 오류로 중단
  - 경로: `audio_path`에 절대 경로·`..`·심볼릭 링크로 아무 파일이나 지정할 수 있었다 → 검증 녹음 폴더 안으로 제한, 서비스·E2E 녹음 저장소 거부
  - 매니페스트 검사 부족: 빈 필수 값·음수·정수 아님·포함<제외 음절·전사자 중복·FINAL 누락·녹음 정보 충돌·열 초과가 그대로 통과하거나 알 수 없는 예외로 끝났다 → 모든 문제를 줄 번호와 함께 한 번에 보고
  - 맞닿은 말소리 구간(끝 = 다음 시작)을 받던 것 → 하나로 표시하도록 거부
  - 결과 폴더가 초 단위 이름이라 같은 초에 다시 실행하면 덮어쓸 수 있었다 → 새 폴더 생성
  - 요약에서 '해당 없음'과 '측정 불가'가 한 칸으로 합쳐져 있었다 → 분리, '측정됐지만 기준 음절 없음' 추가
  - 입력 재현 확인 수단이 없었다 → 매니페스트·녹음 SHA-256 기록
  - macOS에서 없는 파일 보고에 임시 폴더 구조가 드러나는 상대 경로가 나오던 문제 → 매니페스트 기준 경로로 표시
- 확인한 것(합성음, 아동 음성 검증 아님): 같은 입력 2회 실행 결과 동일, 실행 전후 입력 파일 SHA-256 동일, 결과 폴더에 녹음 복사 없음, 보고서에 인식 텍스트·녹음 폴더 절대 경로 없음, 잘못된 매니페스트로 실행하면 측정 없이 중단하고 결과 폴더를 만들지 않음.
- `backend/storage/audio`의 출처 불명 녹음 3개는 이번에도 열거나 사용하지 않았다. 거부 동작은 임시 파일로 만든 저장소로 시험했다.
- **실제 아동 음성 검증은 여전히 수행하지 않았다**(8.1의 4개 조건 미충족).

| 입력 불변(실행 전후 SHA-256), 녹음 미복사 | `SpeechValidationHarnessSelfTest` | 통과 |
| 재현성 | `speechValidation` 2회 실행 후 `cmp`로 results.tsv·summary.md 전체 비교 | 두 파일 모두 바이트 단위 동일(합성음 5녹음) |
| 결과 보존 | 2회 실행 전후 결과 폴더 수 | 3 → 5(기존 폴더 유지), 같은 초 실행은 `newOutputDirectory` 테스트로 확인 |
| 잘못된 입력 | 폴더 밖 경로·음수 음절 매니페스트로 실행 | 측정 없이 오류 2건(줄 번호 포함) 출력, 결과 폴더 생성 안 됨(5 → 5) |
| 요약 상태 구분(해당 없음·측정 불가·기준 음절 없음) | `SpeechValidationTest` | 통과 |
| 일반 테스트와 분리 | `build.gradle`(코드), 전체 실행 결과 | 실행기는 `unitTest`·`integrationTest`·`test`에서 제외, `speechValidation`으로만 실행 |
| 배포물 분리 | `bootJar` 생성 후 목록 확인 | 검증 도구·테스트 리소스·테스트 음성 0건(운영 클래스만 포함) |
| 환경변수 범위 | `build.gradle`(코드) | `SPEECH_VALIDATION_*`는 `speechValidation` 작업에만 명시 전달. 다만 Gradle 테스트 JVM은 실행한 셸의 환경을 물려받으므로 셸에 설정하면 다른 테스트 작업에서도 보일 수 있다. 이 값을 읽는 코드는 실행기뿐이고 실행기는 다른 작업에서 제외된다(코드 확인, 실행으로는 확인하지 않음) |

- 이 점검은 도구의 안전성·재현성 확인이며 아동 음성 검증이 아니다. 합성음 자체 점검의 오차 값(8.7)은 기술 참고일 뿐 아동 음성의 정확도나 허용 오차로 일반화하지 않는다.
