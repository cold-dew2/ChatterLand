# 학습 서비스 확장: 자율 연습, 연습 콘텐츠, 숙제 콘텐츠, 교사 학습 기록

작성: 2026-10-06. 기존 AI/RAG(`docs/design/ai-feedback.md`)는 바꾸지 않았다. 바꾼 것은 프롬프트·검증 규칙 보강뿐이다(7절).

## 1. 기존 구조 분석

| 개념 | 실제 구현 | 판단 |
|---|---|---|
| 연습 콘텐츠 | `exercises`(연습 세트: 카테고리·제목·안내·입력 방식·목표 음소·순서·활성) + `exercise_items`(낱말·문장, 그림·이모지) | 이 구조를 콘텐츠로 그대로 쓴다. 기존 데이터는 5세트·15문항이었다. 난이도·유형·발음 분류 필드는 없었다 |
| 연습 결과 | `practice_attempts`(attempt_type PRACTICE/HOMEWORK/AI_CHAT, analysis_id) + `speech_analyses` | 새 결과 테이블을 만들지 않는다. 지금까지 HOMEWORK는 쓰이지 않았다 |
| 자율 연습 | 이미 있다: 연습하기 → 카테고리 → 세트 → 녹음 → whisper 분석 → `POST /practice/attempts`(PRACTICE) | 같은 화면·분석 파이프라인을 그대로 쓰고, 찾기 화면만 추가했다 |
| 숙제 | `homeworks`(제목·유형 문자열·마감·완료). 콘텐츠와 연결이 없었고 완료는 학생이 직접 누른다 | 콘텐츠 참조 컬럼을 추가했다. 완료 방식은 그대로 둔다 |
| 교사 학습 현황 | 학생 상세의 '학습 현황' 탭(외부 점수·세션 기록) | 연습 기록 패널을 추가했다 |

## 2. DB 변경 (모두 추가형, `schema.sql` 조건부 ALTER)

| 테이블 | 추가 | 설명 |
|---|---|---|
| exercises | `difficulty`, `content_type`, `pronunciation_rule` (NULL 허용), 인덱스 `idx_exercise_filters(active, pronunciation_rule, difficulty, content_type)` | 콘텐츠 분류·필터 |
| homeworks | `exercise_id` (NULL 허용, FK → exercises) | 숙제가 참조하는 연습 세트. NULL이면 기존 자유 숙제 |
| practice_attempts | `homework_id` (NULL 허용, FK → homeworks ON DELETE SET NULL) | 숙제로 한 연습. NULL이면 자율 연습. 숙제를 지워도 기록은 남는다 |

- 신규 테이블: 없음.
- seed: `backend/src/main/resources/data.sql`(Spring 기본 data 위치, `INSERT IGNORE`, 고정 ID 1001~)을 새로 추가했다. 기존 `schema.sql`의 기본 5세트는 그대로다.

## 3. API

| 구분 | API | 내용 |
|---|---|---|
| 추가 | `GET /api/v1/practice-contents` | 검색어(세트 이름·문항 글자)·categoryId·difficulty·rule·contentType 필터, 페이지(최대 50). 학생·교사 모두. 허용 목록에 없는 값은 400 |
| 추가 | `GET /api/v1/practice-contents/{id}` | 세트 하나와 문항 |
| 추가 | `GET /api/v1/teachers/me/students/{studentId}/practice-attempts?type=PRACTICE\|HOMEWORK` | 담당 학생의 연습 기록: 종류, 숙제, 세트, 분석 상태·판정 보류, 목표·인식 문장, 텍스트 일치율(참고), analysisId |
| 추가 | `GET /api/v1/teachers/me/students/{studentId}/practice-summary` | 전체·자율·숙제 횟수, 연습한 세트 수, 최근 연습 시각 |
| 변경(추가 필드) | `POST /api/v1/practice/attempts` | `homeworkId`(선택) 추가. 본인 숙제가 아니면 404, 숙제가 지정한 세트와 다르면 409. 응답에 `attemptType`·`homeworkId` 추가 |
| 변경(추가 필드) | `POST /api/v1/teachers/me/homeworks` | `exerciseId`(선택) 추가. 운영 중인 콘텐츠가 아니면 400. 숙제 응답·목록에 `exerciseId`·`exerciseTitle` 추가 |
| 변경(추가 필드) | `GET /api/v1/students/me/homeworks` | `exerciseId`, `exerciseTitle`, `attemptCount` |
| 변경(추가 필드) | `GET /api/v1/students/me/history` | 연습 기록에 `attemptType`, `analysisId`, `exerciseId` |

- 기존 API 영향: 필드만 추가했다. 기존 요청(homeworkId·exerciseId 없음)은 이전과 똑같이 동작한다.
- 권한
  - 교사 API는 기존 `assignedStudent`(담당 관계 서버 확인)를 쓴다. 다른 선생님이 학생 ID를 넣으면 403/404다.
  - AI 설명은 기존 `GET /teachers/me/speech-analyses/{analysisId}/feedback`(담당 관계 조인)을 그대로 쓴다.
  - 숙제 연습 저장은 학생 본인 숙제인지 서버에서 확인한다.
- 자율 연습 결과의 AI 설명: 기존 학습 피드백은 분석 단위라서 자율 연습 분석에도 그대로 동작한다. 연결 코드를 추가하지 않았다.

## 4. 화면

- **학생**
  - 연습 유형 선택에 '전체 연습 찾기'를 추가했다(`PracticeBrowseScreen`). 검색, 카테고리·난이도·발음 유형·콘텐츠 유형 필터, 더 보기, 최근 연습 3개(숙제 연습 표시)를 제공한다. '연습 시작'을 누르면 기존 `SpeechActivityScreen`으로 넘어간다.
  - 숙제 화면에서 숙제에 지정된 연습이 있으면 '연습하러 가기'가 그 세트를 바로 숙제 연습으로 시작한다(`homeworkId`로 저장). 연습 이름과 연습 횟수도 보여 준다.
  - 히스토리에서 연습 기록에 '자율 연습/숙제 연습' 배지를 표시한다.
- **교사**
  - 숙제 등록 모달에 '연습 콘텐츠(선택)' 검색·선택을 추가했다(`PracticeContentPicker`). 수정할 때는 지정된 콘텐츠를 보여 주기만 한다.
  - 학생 상세 '학습 현황' 탭에 연습 기록 패널을 추가했다(`StudentPracticePanel`).
    - 횟수 요약, 전체·자율·숙제 필터, 기록별 분석 상태와 판정 보류, 목표·인식 문장을 보여 준다.
    - 텍스트 일치율은 "(발음 점수 아님)"으로 표시하고, 발음 평가는 '미평가'로 둔다.
    - 기록마다 '학생이 본 AI 설명 보기'(기존 컴포넌트)를 쓸 수 있다.
  - **텍스트 일치율은 통계(평균 등)로 쓰지 않는다.**
- 공통 분류 이름은 `features/student/utils/practiceLabels.ts` 한 곳에 둔다.

## 5. 연습 콘텐츠 (1,115개)

- **작성·검증 방법**: `backend/scripts/practice-content/` 아래 파일로 만든다.
  - `content_basic.py`, `content_rules.py`: 직접 작성한 낱말·문장
  - `build_seed.py`: 검증 후 `data.sql`을 생성한다.
- 검증은 표기(자모)로 목표 발음이 실제로 들어 있는지 확인하고, 통과하지 못한 항목은 넣지 않는다.
  - 기본 자음: 목표 초성이 들어 있어야 한다.
  - 기본 모음: 목표 중성이 들어 있어야 한다.
  - 받침: 목표 종성이 들어 있어야 한다.
  - 음운 규칙: 표준 발음법 조항(연음 13·비음화 18/19·된소리 23·구개음화 17·유음화 20·격음화 12)이 감지되어야 한다.
  - 종합 발음: 조항이 2개 이상 감지되어야 한다.
  - 예: '깃발'(ㄲ 첫소리로 잘못 넣음), '걸어요'(ㄷ 받침 아님), '몇 시'(어절 경계) 등 7개를 제외했다.
- 통합 테스트(`PracticeContentSeedIntegrationTest`)가 DB에 들어간 음운 규칙 콘텐츠 전부를 **백엔드 `PronunciationRuleDetector`로 다시 판별**해 일치를 확인한다. 생성기와는 별개의 두 번째 검증이다.

- 연습 세트는 245개(세트당 5문항 이하)다. 서로 다른 문장은 1,064개이고, 같은 낱말이 다른 분류에 다시 쓰인 경우가 49개 있다(예: '가방'은 ㄱ 첫소리와 ㅏ 모음 모두).
- 난이도는 규칙으로 정했다.
  - 낱말: 기본 자음·모음·받침은 초급, 음운 규칙은 중급
  - 짧은 문장: 중급
  - 긴 문장(6어절 이상): 고급
  - **언어재활사가 검토한 난이도가 아니다.**
- **분류의 한계**
  - 형태소 분석 없이 표기만으로 판별했다. 그래서 '격음화'의 ㅎ 탈락 등 실제 발음과 다를 수 있는 경우가 있다.
  - 사이시옷, ㄴ 첨가 같은 규칙은 분류에 넣지 않았다.
  - 발음 분류는 콘텐츠의 성질일 뿐 학생 발음을 평가하지 않는다.
- 맞춤법·자연스러움은 작성자가 검토했다. **교사·국어 전문가 검수는 받지 않았다.**
- 단계적 확장: 22개 → 102개 → 500개 → 1,115개 순으로 늘렸고, 각 단계마다 학습 통합 테스트를 통과했다(22개 단계에서 E2E 실제 흐름도 확인).

## 6. 연습 종류 구분의 한계

- 숙제 ID 없이 저장된 연습은 모두 '자율 연습(PRACTICE)'이다. 기존 '수업(세션) 연습'도 지금까지 PRACTICE로 저장되어 왔으므로 교사 화면에서는 '자율 연습'으로 보인다. 세션 연습을 따로 구분할지는 결정이 필요하다.
- 숙제 완료는 지금처럼 학생이 '완료'를 누른다. 숙제 연습을 하면 자동 완료할지는 결정이 필요하다.

## 7. AI 품질 보강 (기존 AI/RAG 구조 유지)

- 프롬프트 버전 `feedback-v2-rag` → `feedback-v3-rag`. 지시 4개를 추가했다.
  - 듣지 않은 발음을 '정확하게·또박또박·잘' 했다고 칭찬하지 말고 노력만 칭찬하기
  - 자모를 이름이 아니라 글자로 쓰기
  - 어려운 용어 대신 쉬운 말 쓰기
  - 연습 방법은 참고 자료의 예시 낱말로만 구체적으로 제안하기
- 검증 규칙 추가
  - 자모 이름(기역·비읍 등)도 자모로 바꿔 근거 검사를 한다.
  - 듣지 않은 발음을 평가하는 표현이 있으면 `AI_UNGROUNDED`로 처리하고 저장하지 않는다.
- **영향**: 프롬프트 버전이 근거 해시에 들어가므로, v2로 만든 설명은 학생 화면에서 '아직 만들지 않음'으로 바뀐다(다시 만들 수 있음). 선생님 화면에서는 저장된 설명이 '이전 근거로 만든 설명'으로 표시된다.
- **실제 호출(2026-10-06, v3, 합성 10건)**
  - 근거 검증 통과 10/10
  - 생성 시간: 평균 6,379ms, 중앙값 5,407ms, p95 9,236ms
  - 개발자 예비 관찰
    - 노력만 칭찬했다.
    - 자모 이름과 '대표음'이 사라졌다.
    - 모든 설명이 자료 예시 낱말로 구체적인 연습을 제안했다(예: 난로·칼날).
  - 교사 검수는 아직 하지 않았다. 표본은 `docs/testing/live-ai-feedback-samples-2026-10-06.json`.

## 8. 하지 않은 것

- **RAG 지식자료 확장(단계 12)**: 지시대로 이번에는 하지 않았다. 표준 발음법 8개 조항(검수 전 DRAFT)은 그대로 있다.
  - 필요한 자료: 조음 위치·방법, 자음·모음 지도, 받침 지도 자료, 교사 승인 설명 예시. 모두 출처·사용 권한을 확인해야 한다.
- 콘텐츠 그림·음성 예시, 콘텐츠 관리(교사·운영자 편집) 화면
- 텍스트 일치율 이외의 학습 통계(기간별 추이 등)
